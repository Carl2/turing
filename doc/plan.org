* Overview

A Turing machine interpreter written in C++23, using =boost::sml= as the
state machine that drives the interpreter's execution loop.

Inspired by Blaise Agüera y Arcas' /What is Intelligence/ — a program is
just a slip of symbols, and data is just another slip. One slip reads and
transforms the other. There is no fundamental distinction between program
and data; both are patterns of symbols on tape.

The machine operates with:
- A *program string* — the sequence of instructions (one slip)
- A *data tape* — a dynamically extending strip of =char= cells (another slip)
- An *instruction pointer* (IP) stepping through the program
- A *data head* (DH) moving over the data tape
- A single =char= *register* as intermediary for read/write

** Instruction Set

| Symbol | Name  | Meaning                                                    |
|--------+-------+------------------------------------------------------------|
| =>     | Right | Move data head right                                       |
| =<=    | Left  | Move data head left                                        |
| =!=    | Write | Write register value to current data cell                  |
| =%=    | Read  | Read current data cell into register                       |
| =[=    | Loop  | Loop anchor (destination of =]= jump)                      |
| =]=    | Back  | If current data cell \ne ='\0'=, jump IP back to matching =[= |

Termination: the machine halts when the IP advances past the end of the program.

** Role of boost::sml

=boost::sml= models the /interpreter's execution state machine/, not the
Turing machine's abstract states. The SML machine drives the fetch-execute
cycle.

*Note:* The original design had multiple states (Idle, Fetch, Execute,
Seek) with sub-events fired via =process_event= inside actions. This was
simplified because SML queues sub-events and processes them /after/ the
current transition completes, causing them to arrive in the wrong state.
The final design uses guards to multiplex a single =run= state:

#+begin_src text
                         ┌──────────────────────────────────────┐
                         │           run                        │
  ┌──────┐   Tick    ┌───┴───────────────────────────────────┐  │
  │ idle │ ───────▶ │  [is_seeking]       / do_seek   ──────┘  │
  └──────┘          │  [should_execute]   / do_execute ────────┘
                    │  [should_halt]      ─────────▶  X (halted)
                    └──────────────────────────────────────────┘
#+end_src

States:
- =idle= — initial state, machine not yet started
- =run=  — active execution (guards determine what happens each tick)
- =X=    — SML terminal state; machine halted

Events:
- =Tick= — advance one execution step (the only event)

Guards (evaluated in order on each =Tick= in =run=):
- =is_seeking=      — context's =seeking= flag is set; seek toward matching =[=
- =should_execute=  — not seeking and IP not past end; execute current instruction
- =should_halt=     — not seeking and IP past end; transition to =X=

The =seeking= flag in =MachineContext= replaces a dedicated Seek state.
When =]= fires and the current cell \ne ='\0'=, the action sets
=seeking=true= and =depth=1=. Subsequent ticks fire =do_seek= (decrement
IP, track bracket depth) until the matching =[= is found.

* Goals and Non-Goals

** Goals
- Implement a working Turing machine interpreter in C++23
- Use =boost::sml= as the central state machine driving execution
- Clean separation: program string vs data tape vs register
- Support all six instructions: =>= =<= =!= =%= =[= =]=
- =]= is *conditional*: jump back only if current data cell \ne ='\0'=
- Handle nested =[= =]= correctly via depth counter during Seek
- Demonstrate with example programs:
  - Copy a cell value
  - Zero-fill a region
  - Simple counter or marker program

** Non-Goals
- GUI or visual tape display (terminal dump is fine)
- Interactive I/O (=stdin= / =stdout= for data)
- Performance optimisation
- Formal Turing completeness proof

* Constraints and Assumptions

- C++23 standard
- =boost::sml= for the interpreter state machine
- =std::deque<char>= for the data tape (extends both directions)
- Blank cell value: ='\0'= (null byte)
- Program is a =std::string= passed at construction
- Initial data tape content: optional =std::string=, defaults to all blank
- Data head starts at position 0; IP starts at position 0
- Nested =[= =]= matched correctly using a depth counter in the Seek state
- No self-modifying code (program string is read-only)

* Risks and Open Questions

- =boost::sml= lambda/guard syntax can be verbose — validate with a
  minimal example before wiring everything up
- Seek state depth counter lives in TuringMachine, not in SML states
  (SML guards read machine state via dependency injection)
- Moving left past position 0: =deque::push_front= + adjust head index
  to stay at 0 (or use signed index with offset tracking)
- Should unknown characters in the program be treated as no-ops or errors?
  *Resolved:* unknown characters are rejected at validation time (factory
  returns =MachineError::UnknownInstruction=). Programs must consist only
  of the six instruction characters.

* Example Programs

** Copy cell 0 to cell 1

Program: ~%>!~

#+begin_src text
  Initial tape: [ 'A' | '\0' ]
                   ↑ head

  Step 1: %    → reg = 'A',  head stays at 0
  Step 2: >    → head moves to 1
  Step 3: !    → cell 1 = 'A'

  Final tape:   [ 'A' | 'A' ]
                         ↑ head
#+end_src

** Zero a cell using a blank cell

Program: ~>>%<<!~

#+begin_src text
  Initial tape: [ 'X' | 'Y' | '\0' ]
                   ↑ head

  Step 1: >    → head to 1
  Step 2: >    → head to 2
  Step 3: %    → reg = '\0' (blank cell)
  Step 4: <    → head to 1
  Step 5: <    → head to 0
  Step 6: !    → cell 0 = '\0'

  Final tape:   [ '\0' | 'Y' | '\0' ]
                    ↑ head
#+end_src

** Loop: copy cells until blank

Program: ~[%>!>%<<]~

#+begin_src text
  Initial tape: [ 'A' | '\0' | 'B' | '\0' | '\0' ]
                   ↑ head

  Iteration 1:
    [  → anchor
    %  → reg = 'A'
    >  → head to 1
    !  → cell 1 = 'A'
    >  → head to 2
    %  → reg = 'B'
    <  → head to 1
    <  → head to 0
    ]  → cell 0 = 'A' ≠ '\0' → jump to [

  Iteration 2:
    [  → anchor
    %  → reg = 'A'      (cell 0 still 'A')
    >  → head to 1
    !  → cell 1 = 'A'   (overwrite again)
    >  → head to 2
    %  → reg = 'B'
    <  → head to 1
    <  → head to 0
    ]  → cell 0 = 'A' ≠ '\0' → jump to [  ← infinite loop!

  Note: to terminate, the loop body must eventually set
  the cell under the head at ] to '\0'.
#+end_src

This example shows why loop design requires care — you need a
deliberate exit strategy (zeroing the check cell).
